# IndexNow Yandex — описание и установка

## 📖 О программе

**IndexNow Yandex** — портативная десктопная утилита для Windows, которая
отправляет URL-адреса вашего сайта на переиндексацию по протоколу
[IndexNow](https://www.indexnow.org/documentation).

Программа принимает список ссылок, проверяет их на корректность, отсеивает
дубликаты и мусор, а затем одним или несколькими пакетами отправляет их в API
выбранных приёмников: **Яндекс**, **Bing** или общий `api.indexnow.org`
(по протоколу движки делят присланные URL между собой). Результат отправки
и подробная статистика отображаются прямо в окне.

### Что умеет

| Возможность | Описание |
|---|---|
| **Массовая отправка** | До 10 000 URL за один запрос, автоматическая разбивка на пакеты при большем объёме |
| **Несколько приёмников** | Яндекс, Bing и общий `api.indexnow.org`; можно отправлять в несколько сразу |
| **Валидация URL** | Проверка схемы (`http`/`https`), хоста, порта; отклонение мусора до отправки |
| **Автоопределение домена** | Если поле «Домен» пустое, хост берётся из первой ссылки |
| **Дедупликация** | Удаление повторов с учётом регистра схемы и хоста, но с сохранением регистра пути |
| **Поддержка IDN** | Кириллические домены (`.рф`, умляуты) автоматически конвертируются в Punycode |
| **Percent-encoding** | Пути и query-параметры с кириллицей кодируются по RFC 3986 |
| **Строгое сравнение хостов** | `example.com` ≠ `www.example.com`, `http://` ≠ `https://` |
| **Смешанные схемы** | Если в списке есть и `http://`, и `https://` — отправка идёт двумя запросами |
| **keyLocation** | Автодополнение относительного пути до полного URL, проверка хоста и схемы, предупреждение об области действия файла ключа |
| **Статистика и итог** | Отправлено / отклонено с разбивкой по причинам; в конце — сводка по HTTP-кодам для каждого приёмника |
| **Прогресс** | Индикатор выполнения по числу отправленных пакетов |
| **Автоматические retry** | Повторная попытка при `429` и `5xx` с экспоненциальной задержкой (2/4/8 с) |
| **Устойчивость** | Потокобезопасный UI, корректное завершение без зависаний в диспетчере задач |
| **Журнал** | Подробный лог в файле — важно для сборки без консоли |
| **Сохранение настроек** | Домен, ключ, `keyLocation`, приёмники и размер окна запоминаются между запусками |

### Что нужно перед запуском

1. **Ключ IndexNow** — строка длиной 8–128 символов, состоящая из
   `[A-Za-z0-9-]` (латинские буквы, цифры и дефис).
2. **Файл с ключом на сайте** — разместите его по адресу вида
   `https://ваш-сайт.ru/ваш-ключ.txt`. Содержимое файла — только сам ключ,
   без разметки и пробелов. Это подтверждает движку, что вы владелец сайта.
3. **Windows** (или любая ОС с Python 3.10+), для сборки `.exe` — Windows.

> ⚠️ IndexNow не гарантирует индексацию — он только уведомляет поискового
> робота о наличии или изменении страницы.

## 🖥️ Интерфейс

### Поля ввода

| Поле | Обязательное | Описание |
|---|---|---|
| **Домен (host)** | Нет | Хост сайта без схемы и пути (`example.com`). Если пусто или `example.com` — будет подставлен из первой ссылки |
| **Ключ IndexNow** | Да | 8–128 символов `[A-Za-z0-9-]`; подчёркивание не допускается |
| **keyLocation** | Нет | Полный URL файла с ключом. Можно указать относительный путь — программа дополнит хостом и схемой |
| **Куда отправлять** | Да | Один или несколько приёмников: Яндекс, Bing, IndexNow (общий) |
| **Ссылки** | Да | По одной на строке. До 10 000 в одном запросе, больше — автоматически разбивается на пакеты |

Над полем ссылок есть кнопки **«Вставить из буфера»**, **«Загрузить из файла»**
(UTF-8 или CP1251) и **«Очистить»**.

### Горячие клавиши

- `Ctrl+C` / `Ctrl+V` / `Ctrl+X` / `Ctrl+A` — работают в **любой раскладке
  клавиатуры** (в том числе русской);
- `Cmd+A` — выделить всё на macOS;
- `Ctrl+Enter` — отправить;
- правая кнопка мыши — контекстное меню (вырезать, копировать, вставить,
  выделить всё).

## 🚀 Установка с исходников

### Шаг 1. Установите Python

Скачайте Python 3.10 или новее с
[python.org/downloads](https://www.python.org/downloads/windows/).

> ⚠️ При установке обязательно отметьте галочку **«Add Python to PATH»**.

Проверьте установку:

```powershell
python --version
pip --version
```

Оба должны вывести версии без ошибок. Если команды не найдены — Python не
добавлен в `PATH`, переустановите с нужной галочкой.

### Шаг 2. Скачайте проект

Скопируйте папку проекта в удобное место, например `E:\IndexNowYandex`, и
проверьте структуру:

```powershell
cd E:\IndexNowYandex
dir
```

Должны быть видны `run.py` и папка `indexnow_app`.

### Шаг 3. Установите зависимости

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

> `python -m pip` предпочтительнее `pip`, потому что гарантированно использует
> тот же интерпретатор, что и `python`.

### Шаг 4. Запустите программу

```powershell
python run.py
```

Альтернативный способ:

```powershell
python -m indexnow_app
```

Откроется окно программы.

## 📦 Сборка портативного `.exe`

### Обычная сборка

```powershell
python -m PyInstaller --clean --noconfirm IndexNow.spec
```

или просто запустите **`build.bat`** — он поставит зависимости и пересоберёт exe.

### Результат

```
E:\IndexNowYandex\
├── build\                       (временные файлы — можно удалить)
├── dist\
│   └── IndexNow.exe             ← портативный файл
├── IndexNow.spec
├── run.py
└── indexnow_app\
```

Готовый файл `dist\IndexNow.exe` можно скопировать на любой компьютер с
Windows. Python на целевой машине **не требуется**.

### Отладочная сборка

Если `.exe` падает или не запускается — соберите с консолью, чтобы увидеть
traceback:

```powershell
python -m PyInstaller --onefile --noconsole=False --name "IndexNow_Debug" run.py
.\dist\IndexNow_Debug.exe
```

После диагностики пересоберите обычным способом. Стоит также заглянуть в
журнал приложения (см. «Где хранятся данные»).

### Если `pyinstaller` не распознаётся

Команда `pyinstaller` может быть не в `PATH`, даже если пакет установлен.
Всегда работает запуск через модуль:

```powershell
python -m PyInstaller --version
python -m PyInstaller --clean --noconfirm IndexNow.spec
```

Если это помогло, но хочется использовать просто `pyinstaller`, добавьте
в `PATH` папку со скриптами Python:

```powershell
python -c "import sysconfig; print(sysconfig.get_path('scripts'))"
```

Вывод — путь вида
`C:\Users\ВашеИмя\AppData\Local\Programs\Python\Python312\Scripts`. Добавьте
его в переменную среды `Path` через «Параметры системы → Переменные среды».

## 🧪 Быстрая проверка работоспособности

1. Откройте программу.
2. В поле **Домен** оставьте `example.com` — он будет заменён автоматически.
3. В поле **Ключ** введите тестовый ключ, например `test-key-123456`.
4. Убедитесь, что приёмник **Яндекс** отмечен.
5. В поле **Ссылки** вставьте:
   ```
   https://example.com/page1
   https://example.com/page1
   https://example.com/page2
   https://other-site.com/page
   просто_текст
   ```
6. Нажмите **Отправить**.

Программа должна показать в логе:

```
============================================================
Домен определён автоматически: example.com
Статистика по введённым данным:
   Всего строк в поле ввода: 5
   К отправке:               2
   Отклонено:                3
      - дубликаты:           1
      - некорректные URL:    1
      - чужой домен:         1
Отправка 2 URL на example.com (1 пакет(ов))...
HTTP-код ответа: 403. Неверный ключ. Проверьте ключ и расположение файла с ключом.
```

Код `403` в этом примере ожидаем — ключ `test-key-123456` не опубликован на
сайте. Это доказывает, что программа работает: данные ушли на сервер, ответ
пришёл, интерфейс отреагировал.

## 🔑 Как получить рабочий ключ и настроить сайт

1. Придумайте ключ: 8–128 символов из `[A-Za-z0-9-]`. Пример:
   `a1b2c3d4-e5f6-7890`.
2. Создайте на сайте файл, например
   `https://example.com/a1b2c3d4-e5f6-7890.txt`.
3. Содержимое файла — **только сам ключ**, без HTML, без кавычек, без
   переводов строки в начале:
   ```
   a1b2c3d4-e5f6-7890
   ```
4. Убедитесь, что файл доступен по HTTPS и отдаётся с кодом `200`.
5. В программе укажите:
   - **Домен**: `example.com`
   - **Ключ**: `a1b2c3d4-e5f6-7890`
   - **keyLocation**: `https://example.com/a1b2c3d4-e5f6-7890.txt`

После этого запросы будут приниматься с кодом `200` или `202`.

> Если файл ключа лежит не в корне, а в подкаталоге (например,
> `/catalog/key.txt`), он покрывает только URL с этим префиксом. Программа
> предупредит, если часть ссылок вне этой области — движок может отклонить
> их с кодом `422`.

## ⚙️ Где хранятся данные

Каталог `%LOCALAPPDATA%\IndexNow\`:

| Файл | Что внутри |
|---|---|
| `settings.json` | домен, ключ, `keyLocation`, выбранные приёмники, размер окна |
| `indexnow.log` | журнал работы (ротация: 256 КБ, 2 файла) |

Настройки сохраняются при нажатии «Отправить» и при закрытии окна. Ключ
IndexNow не является секретом — он публикуется в открытом файле на сайте,
поэтому хранится без шифрования.

## ❓ Частые вопросы

**Какой код ответа считается успешным?**

- `200 OK` — страницы приняты на переиндексацию.
- `202 Accepted` — ключ принят и ожидает проверки, отправьте ещё несколько
  адресов в течение суток.

Остальные коды (`400`, `403`, `404`, `405`, `422`, `429`, `5xx`) программа
расшифровывает в логе.

**Почему ссылки с `www.` отклоняются, если домен введён без `www.`?**

Это осознанное поведение: `example.com` и `www.example.com` — технически
разные хосты. Вводите домен ровно в той форме, в которой он фигурирует
в ссылках.

**Почему часть ссылок `http://`, а часть `https://` — они не отправятся вместе?**

IndexNow требует единый протокол для `keyLocation` и списка URL. Программа
автоматически отправляет две группы отдельными запросами: сначала все
`http://`, затем все `https://`. Если `keyLocation` был введён явно
(со схемой), он не переписывается; если относительный — получает схему группы.

**Как часто можно отправлять одни и те же URL?**

Рекомендуется не чаще, чем раз в 10 минут. При превышении лимитов сервер
возвращает `429`, и программа автоматически повторит запрос с задержкой
2/4/8 секунд.

**Что делать, если `.exe` не запускается на другом компьютере?**

Убедитесь, что это Windows и установлены обновления Microsoft Visual C++
Redistributable (обычно уже есть). Соберите отладочную версию с консолью,
чтобы увидеть точную причину, и проверьте `indexnow.log`.

**Где хранятся ключ и домен между запусками?**

В `%LOCALAPPDATA%\IndexNow\settings.json` (см. раздел «Где хранятся данные»).
Если не хотите хранить ключ, очистите поле и сохраните — при следующем запуске
оно останется пустым.

**Нужно ли отправлять в Bing отдельно, если уже отправил в Яндекс?**

Нет: по протоколу движки делят присланные URL между собой. Отправка
в несколько приёмников нужна для устойчивости, если один из них недоступен.

## ⚙️ Технические детали

- **Язык**: Python 3.10+
- **GUI**: Tkinter (входит в стандартную поставку Python для Windows)
- **HTTP**: `requests` + `urllib3.Retry` (retry на 429, 500, 502, 503, 504)
- **Многопоточность**: фоновый `threading.Thread` (daemon), обмен с UI через
  `queue.Queue` и `root.after`
- **Стандарты**: URL-кодирование по RFC 3986, IDN по RFC 5890,
  спецификация IndexNow 1.0
- **Проверки**: ruff, mypy, pytest (90 тестов)
- **Лицензия**: используйте свободно на свой страх и риск

## 📋 Ограничения

- Не гарантирует индексацию — только уведомляет поискового робота.
- Не проверяет существование страниц — только формат URL.
- Порт в URL не поддерживается: ссылка `example.com:8080` отклоняется,
  поскольку IndexNow работает с hostname без порта.
- Авторизация в URL (`user:pass@host`) не приветствуется IndexNow: такие
  ссылки отправляются как есть, но движок может их отклонить.
- Нет отмены уже начатой отправки — прервать пакет можно только закрытием окна.
